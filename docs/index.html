Local MCP server · Selenium · on-device ML

Maps your site, then tells you what to test.

Point Cartographer at a URL and it charts the site: the pages, the user journeys that run through them, and the elements most likely to break. It hands back prioritised test cases, stable locators you can find by describing an element in plain English, and an optional ARIA review.

How it works

From a URL to a test plan

Everything runs on your machine. Chrome does the browsing, a small embedding model does the judging, and your MCP client gets structured results back.

Crawl

Headless Chrome, driven by Selenium, visits one page or a whole site breadth-first, staying on the same site and signing in if you give it credentials.

Analyse

An analyser injected into each page reads the DOM and scores every interactive element with all-MiniLM-L6-v2, falling back to heuristics if the model can’t load.

Connect

Pages are stitched into user journeys — login, registration, checkout, search, multi-step forms — using heuristic and ML-based detectors.

Report

You get prioritised test cases with steps and expected results, stable CSS/XPath locators, and Markdown or JSON ready to paste into a plan.

What you get

Built for people who write the tests

Site-wide crawling

Crawl one page or up to fifty, with depth limits, timeouts you control, and automatic login for protected areas.

Journey detection

Finds the flows that matter across pages, with a confidence score, and exports them as Markdown with flow diagrams.

Risk-ranked elements

Each element gets an intent score from 0–100, mapped to critical, high, medium or low priority so you test what matters first.

Plain-English locators

Ask for “the checkout button” and get a stable selector — even when the button actually says “Proceed to payment”.

ARIA advisory

An opt-in review that flags ARIA likely to mislead assistive-technology users, and says what removing it would lose.

Runs the critical tests

Execute the critical test cases straight away in the browser, with retries, using auto-generated semantic tools.

In practice

Ask your assistant, get a test case

Cartographer speaks MCP, so any compatible client can call it. Here is a call to crawl_and_analyze and one of the test cases it returns.

Request

{
  "url": "https://example.com/login",
  "format": "json",
  "ariaAudit": true
}

Then

{
  "description": "the submit button in the login form"
}

One generated test case (abridged)

{
  "name": "Submit login form",
  "priority": "critical",
  "actionType": "submit",
  "intentScore": 92,
  "locator": "form#login button[type='submit']",
  "preconditions": [
    "User is on the login page"
  ],
  "steps": [
    "Fill username and password",
    "Click the submit button"
  ],
  "expectedResults": [
    "User is signed in and redirected"
  ]
}

Reference

Seven MCP tools

Expand any tool for its inputs. The full reference, with every option and output format, is in USAGE.md.

01crawl_and_analyzeCrawl one URL, score its elements and generate test cases.›

format is markdown (default), json or markdown-summary. ariaAudit adds the ARIA advisory to the result.

{ "url": "https://example.com", "format": "json", "ariaAudit": false }
02get_element_locatorFind a stable CSS/XPath locator by describing the element.›

Looks up elements from the most recent crawl, matching by meaning as well as by shared words. Uses a local ~23 MB embedding model downloaded on first use; set CARTOGRAPHER_SEMANTIC_LOCATOR=off for keyword matching only.

{ "description": "the submit button in the login form" }
03run_critical_testsCrawl afresh, then run the critical tests in the browser.›

Runs test cases with an intent score of 50 or more. Only url is required; testIds narrows the run and retryCount re-runs failures.

{ "url": "https://example.com", "testIds": ["test-1"], "retryCount": 1 }
04audit_ariaAdvisory review of ARIA that could mislead assistive tech.›

No ARIA is better than bad ARIA. Each advisory says what is wrong, what a user experiences, what to do instead, and what would be lost if the ARIA were removed. It never fails a run.

{ "url": "https://example.com", "format": "markdown" }
05crawl_multi_pageCrawl a whole site and detect workflows across pages.›

Breadth-first and same-site. maxPages 2–50 (default 10), maxDepth 1–5 (default 3). With credentials it signs in before crawling protected pages. Returns a sessionId kept for one hour.

{
  "startUrl": "https://example.com",
  "maxPages": 10,
  "workflowStrategy": "both",
  "credentials": { "username": "user", "password": "secret" }
}
06get_workflow_by_nameFetch one detected workflow from a crawl session.› 
{ "sessionId": "session_…", "workflowName": "login_flow" }
07export_workflow_visualizationExport workflows as Markdown with flow diagrams.›

workflowIds is optional (default: all). format is individual, comparison or full (default).

{ "sessionId": "session_…", "format": "full" }

Get started

Running in five minutes

You need Node.js 18 or later and Google Chrome. Selenium Manager fetches chromedriver for you.

  1. Clone and install 
    git clone https://github.com/AutomatedTester/cartographer.git
cd cartographer
npm install
  2. Build

    The server injects build/analyzer.browser.js into every page it crawls, so build both.

    npm run build && npm run build:browser
  1. Point your MCP client at it

    For Claude Desktop, add this to claude_desktop_config.json, using the absolute path to your clone.

    {
  "mcpServers": {
    "cartographer": {
      "command": "node",
      "args": ["/path/to/cartographer/build/index.js"]
    }
  }
}
  2. Ask for a map

    “Crawl https://example.com and tell me what I should test first.”

Environment variables

All optional. The older WEBMCP_* names are still read when the CARTOGRAPHER_* one is unset.

VariableEffect
CARTOGRAPHER_HEADED=1Show the Chrome window instead of running headless
CARTOGRAPHER_SEMANTIC_LOCATOR=offget_element_locator uses keyword matching only
CARTOGRAPHER_LOCATOR_MODELEmbedding model for locators: a Hugging Face id or a local directory, such as a fine-tuned model
CARTOGRAPHER_LOCATOR_MIN_SIMILARITYMinimum similarity for a meaning-only locator match; set it for a fine-tuned model
HF_TOKENHugging Face token, needed only for a private locator model
